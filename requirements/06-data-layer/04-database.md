# Database — Room Multiplatform

The single Room database lives in `:data-services:database`. It holds **all** local persistence: tokens, user profile, weight history, drafts, cached server data. There is **one** `@Database` class per app.

## `Database` shape

```kotlin
@Database(
    entities = [
        TokenEntity::class,
        UserActiveEntity::class,

        UserEntity::class,
        UserStatsEntity::class,
        UserExcludedMuscleEntity::class,
        UserExcludedEquipmentEntity::class,
        WeightHistoryEntity::class,

        EquipmentEntity::class,
        EquipmentGroupEntity::class,

        MuscleEntity::class,
        MuscleGroupEntity::class,

        ExerciseExampleEntity::class,
        ExerciseExampleBundleEntity::class,
        ExerciseExampleComponentsEntity::class,
        ExerciseExampleEquipmentEntity::class,
        ExerciseExampleSearchPrefixEntity::class,

        TrainingEntity::class,
        ExerciseEntity::class,
        IterationEntity::class,

        DraftTrainingEntity::class,
        DraftExerciseEntity::class,
        DraftIterationEntity::class,

        GoalEntity::class,
    ],
    version = 5,
    exportSchema = true,
)
@TypeConverters(StringListConverter::class)
@ConstructedBy(DatabaseConstructor::class)
public abstract class Database : RoomDatabase() {

    public abstract fun userActiveDao(): UserActiveDao
    public abstract fun tokenDao(): TokenDao
    public abstract fun userDao(): UserDao
    public abstract fun weightHistoryDao(): WeightHistoryDao
    public abstract fun equipmentDao(): EquipmentDao
    public abstract fun trainingDao(): TrainingDao
    public abstract fun draftTrainingDao(): DraftTrainingDao
    public abstract fun exerciseExampleDao(): ExerciseExampleDao
    public abstract fun muscleDao(): MuscleDao
    public abstract fun goalDao(): GoalDao
}
```

Rules:

- **One `Database` class.** Multiple databases are not used. Cross-table relations need a shared file.
- **`@Database(entities = [...], version = N)`** — every `@Entity` is registered.
- **`exportSchema = true`** — Room writes JSON schema files to `data-services/database/schemas/` for audit and migration testing.
- **`@TypeConverters(StringListConverter::class)`** — register every TypeConverter at the class level. Don't put TypeConverters on individual entities.
- **`@ConstructedBy(DatabaseConstructor::class)`** — Room generates `DatabaseConstructor` (expect/actual) to bridge platform construction.
- **One abstract DAO accessor per DAO.** Method name matches the DAO class name in lowerCamelCase.

## `DatabaseConstructor`

```kotlin
// :data-services:database/DatabaseBuilder.kt (commonMain) — same file as the builder expect
@Suppress("NO_ACTUAL_FOR_EXPECT", "EXPECT_ACTUAL_CLASSIFIERS_ARE_IN_BETA_WARNING")
internal expect object DatabaseConstructor : RoomDatabaseConstructor<Database> {
    override fun initialize(): Database
}
```

Generated by Room on each platform. The `@Suppress` annotations are required because Room Multiplatform's `RoomDatabaseConstructor` is currently in beta.

The actual implementations are emitted by Room's KSP processor — you don't write them. The constructor lives in the same `DatabaseBuilder.kt` file as the builder `expect fun`, not in a separate file.

## `DatabaseBuilder` (expect/actual)

```kotlin
// :data-services:database/DatabaseBuilder.kt (commonMain)
internal expect fun NativeContext.getDatabaseBuilder(): Database
```

### Android

```kotlin
// androidMain
internal actual fun NativeContext.getDatabaseBuilder(): Database {
    val appContext = this.context.applicationContext
    val dbFile = appContext.getDatabasePath("<product>_database.db")
    return Room.databaseBuilder<Database>(
        context = appContext,
        name = dbFile.absolutePath,
    )
        .addMigrations(*DatabaseMigrations.all)
        .fallbackToDestructiveMigration(dropAllTables = true)
        .setQueryCoroutineContext(Dispatchers.IO)
        .build()
        .also { it.openHelper.writableDatabase }   // warm-up
}
```

### iOS

```kotlin
// iosMain
internal actual fun NativeContext.getDatabaseBuilder(): Database {
    val dbFilePath = documentDirectory() + "/<product>_database.db"
    return Room.databaseBuilder<Database>(
        name = dbFilePath,
    )
        .addMigrations(*DatabaseMigrations.all)
        .fallbackToDestructiveMigration(dropAllTables = true)
        .setDriver(BundledSQLiteDriver())
        .setQueryCoroutineContext(Dispatchers.IO)
        .build()
}

@OptIn(ExperimentalForeignApi::class)
private fun documentDirectory(): String {
    val documentDirectory = NSFileManager.defaultManager.URLForDirectory(
        directory = NSDocumentDirectory,
        inDomain = NSUserDomainMask,
        appropriateForURL = null,
        create = false,
        error = null,
    )
    return requireNotNull(documentDirectory?.path)
}
```

### Common parts

- **`addMigrations(*DatabaseMigrations.all)`** — registers all migration objects.
- **`fallbackToDestructiveMigration(dropAllTables = true)`** — **intentional** on both platforms. If a migration is missing or fails, the database is wiped. The app handles re-fetching from the backend. See "Destructive migration policy" below.
- **`setQueryCoroutineContext(Dispatchers.IO)`** — Room's coroutine queries run on IO.
- **Android-only `openHelper.writableDatabase`** — synchronously opens the DB at construction, ensuring readiness before the first query. Avoids first-query latency on Android.
- **iOS-only `setDriver(BundledSQLiteDriver())`** — uses the bundled SQLite implementation (`androidx.sqlite-bundled`) instead of the system SQLite. Required because Room Multiplatform's iOS support depends on the bundled driver.

## Destructive migration policy

`fallbackToDestructiveMigration(dropAllTables = true)` is **intentional**. The reasoning:

- The app caches server data — the source of truth is the backend.
- The app handles auth tokens locally — but on token wipe, the user re-logs.
- The app has drafts — drafts can be lost on schema breakage; this is acceptable (treated like dropped pages in a notebook).
- Maintaining backwards-compatible migrations for **every** schema change is expensive; the team owns the cost of a wipe per breaking schema bump.

**When this policy is acceptable:**

- Server is the source of truth.
- Local-only data (drafts, settings) is non-critical or has its own backup mechanism.

**When it is NOT acceptable:**

- Local-only data that can never be regenerated (offline-first apps, journaling apps).

For a new product evaluating this trade-off, decide at project start. The reference repo chose acceptable wipes; document the choice for your project.

## DI

```kotlin
@Module(includes = [ContextModule::class])
@ComponentScan
public class DatabaseModule {

    @Single
    internal fun provideDatabase(nativeContext: NativeContext): Database =
        nativeContext.getDatabaseBuilder()

    @Single internal fun provideTokenDao(db: Database): TokenDao = db.tokenDao()
    @Single internal fun provideUserDao(db: Database): UserDao = db.userDao()
    @Single internal fun provideWeightHistoryDao(db: Database): WeightHistoryDao = db.weightHistoryDao()
    @Single internal fun provideUserActiveDao(db: Database): UserActiveDao = db.userActiveDao()
    @Single internal fun provideGoalDao(db: Database): GoalDao = db.goalDao()
    @Single internal fun provideEquipmentDao(db: Database): EquipmentDao = db.equipmentDao()
    @Single internal fun provideExerciseExampleDao(db: Database): ExerciseExampleDao = db.exerciseExampleDao()
    @Single internal fun provideMuscleDao(db: Database): MuscleDao = db.muscleDao()
    @Single internal fun provideTrainingDao(db: Database): TrainingDao = db.trainingDao()
    @Single internal fun provideDraftTrainingDao(db: Database): DraftTrainingDao = db.draftTrainingDao()
}
```

- **`@Single`** on every provider — DAOs are stateless and DB-backed; reuse instances.
- **`@Module(includes = [ContextModule::class])`** — `DatabaseModule` needs `NativeContext`.
- DAOs are exposed via top-level provider methods so Koin resolves them without scanning the entire Database class.

## Anti-patterns

- **Multiple `@Database` classes.** Use one.
- **Skipping `exportSchema = true`** — losing the schema audit trail makes migrations risky.
- **TypeConverters on entities** — they belong on `Database`.
- **`fallbackToDestructiveMigration(dropAllTables = false)` (the default)** — drops only the migration target table; can leave foreign-key references dangling.
- **Forgetting `it.openHelper.writableDatabase` on Android** — first-query latency.
- **Using `androidx.sqlite-bundled`** on Android — Room uses the system SQLite on Android; `bundled` is for iOS.
- **Storing access tokens in DataStore instead of Room.** Tokens go in `TokenEntity` so the foreign-key relationship to `UserEntity` is enforced.
