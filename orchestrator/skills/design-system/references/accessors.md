# `AppString`, `AppDrawable`, `AppIcon`

> **Illustrative domain.** Code blocks below use `Note` / `Tag` / `User` as the generic
> `<Entity>` / `<RelatedEntity>` for examples. Substitute identifiers from your product domain.

These three objects under `AppTokens` expose Compose Multiplatform Resources. They are thin
wrappers that exist for **consistency** — every resource is reached through `AppTokens.*`,
not through Compose Resources directly.

## `AppString`

```kotlin
public object AppString {
    @Composable
    public fun res(value: StringResource, vararg formatArgs: Any): String {
        return stringResource(value, *formatArgs)
    }
}
```

Usage:

```kotlin
Text(text = AppTokens.strings.res(Res.string.note_title))

// with format args
Text(text = AppTokens.strings.res(Res.string.amount_value, amount.value, unit))   // "%1$.1f %2$s"
```

The function delegates to `org.jetbrains.compose.resources.stringResource`. Use this
**everywhere** in Composables — never import `stringResource` directly.

For plurals:

```kotlin
// You can either add an overload to AppString:
@Composable
public fun plural(value: PluralStringResource, quantity: Int, vararg formatArgs: Any): String =
    pluralStringResource(value, quantity, *formatArgs)

// Or call pluralStringResource directly from the Composable when convenient
```

In ViewModels, use `StringProvider.get(...)` / `StringProvider.plural(...)` instead (see
the ui-feature skill, references/state.md).

## `AppDrawable`

```kotlin
public object AppDrawable {
    @Composable
    public fun res(value: DrawableResource): Painter {
        return painterResource(value)
    }
}
```

Usage (drawables in the template are raster product imagery, not icons — see
`AppIcon` below for `ImageVector` icons):

```kotlin
Image(
    painter = AppTokens.drawables.res(Res.drawable.note_thumbnail),
    contentDescription = null,
    modifier = Modifier.size(AppTokens.dp.noteCard.icon),
)
```

Same rule: never call `painterResource` directly outside `AppDrawable`.

## `AppIcon`

```kotlin
public object AppIcon
```

`AppIcon` is an empty marker object. Each icon is registered as a top-level
`public val AppIcon.<Name>: ImageVector` extension property in
`:design-system:resources:provider/icons/<Name>.kt`, e.g.:

```kotlin
public val AppIcon.Mail: ImageVector
    get() = _Mail ?: ImageVector.Builder(name = "Mail", ...).apply { ... }
        .build().also { _Mail = it }

@Suppress("ObjectPropertyName")
private var _Mail: ImageVector? = null
```

Callers reach an icon via `AppTokens.icons.Mail`, `AppTokens.icons.ArrowLeft`,
`AppTokens.icons.Search`, etc. Names are **PascalCase** to match the `ImageVector`
convention even though they are properties — the imported extension reads naturally at the
call site (`AppTokens.icons.Mail`).

Adding a new icon = drop a new `<Name>.kt` file into `icons/` exporting
`public val AppIcon.<Name>: ImageVector`. No registration step. If your product prefers
drawables for icons instead of `ImageVector`s, route them through
`AppTokens.drawables.res(...)` — `AppIcon` stays an empty marker and the new accessor uses
`AppTokens.drawables`. (Step-by-step icon authoring: `cookbook-resource.md` § Add an icon.)

## Resource layout

```
:design-system:resources:provider/
  src/commonMain/composeResources/
    values/strings.xml              # default (English)
    values-<locale>/strings.xml     # one folder per non-default locale
    drawable/                       # raster (.webp) and / or vector drawables
    font/                           # font files
```

`Res.string.foo`, `Res.drawable.bar`, `Res.font.baz` — all generated by Compose Resources
from the directory structure. This template does not currently ship a
`values/plurals.xml`; add one (and a per-locale variant in each `values-XX/`) only when a
plural string is actually needed.

### String resource conventions

- **All keys `snake_case`** — `note_title`, `note_archive_apply`,
  `error_no_internet_description`.
- **Descriptive, not numbered.** `title1`/`title2`/`title3` is forbidden; pick semantic
  names.
- **One file per locale.** `values/strings.xml`, `values-<locale>/strings.xml`, etc.
- **Plurals in `plurals.xml`** with `quantity="one|few|many|other"` (locale-dependent:
  English has `one|other`; many other languages require `one|few|many|other` — consult the
  CLDR plural rules for each locale).
- **Format args** use positional placeholders (`%1$s`, `%2$d`) for multi-arg strings.

### Drawable resource conventions

- **All names `snake_case`** (`note_thumbnail`, `tag_badge`, `empty_state`). Use bare
  nouns without `ic_*` / `img_*` / `bg_*` prefixes — drawables
  here are raster illustrations and product imagery, not icons (icons are `ImageVector`s
  under `icons/`). Add a prefix only when a single product really mixes domains and the
  suffix-less name would collide.
- **`.webp`** is the default format in the template (small, fast). Use SVG / `.xml`
  vector when the asset is line-art that needs to scale crisply; use PNG only when lossless
  encoding is required.
- **One file per resource.** No texture atlases or sprite sheets.

### Font conventions

- **Names match family + weight:** `<typeface>_regular`, `<typeface>_medium`,
  `<typeface>_bold`.
- **Variable fonts** can be a single file (`manrope.ttf`) but the template uses one
  file per weight for compatibility.

## Why a wrapper

`AppTokens.strings.res(Res.string.foo)` is one character longer than
`stringResource(Res.string.foo)`. The win:

- All resource access flows through `AppTokens` — same entry point as colors, dp,
  typography.
- A future change (e.g. fallback to a default locale, instrumentation hook for missing
  strings) lands in one place.
- New contributors learn one pattern ("everything visual comes from `AppTokens`") instead
  of two ("strings from `stringResource`, colors from `AppTokens.colors`").

## Anti-patterns

- **`androidx.compose.ui.res.stringResource(R.string.foo)`** — Android-only, breaks iOS
  build.
- **`painterResource(R.drawable.foo)`** from `androidx.compose.ui.res` — same.
- **Hardcoded strings:** `Text("Welcome")`. Forbidden — extract to `strings.xml`.
- **Hardcoded English in resources:** every key has an entry in each
  `values-<locale>/strings.xml`. Missing translations must be fixed before merging.
- **Reading `Res.string.foo` outside `AppTokens.strings.res(...)`.** Direct
  `stringResource(Res.string.foo)` is allowed only inside the `AppString` impl itself.
- **String concatenation in code:** `"$greeting, $name"`. Build a single resource:
  `welcome_user = "Welcome, %s"` and use format args.
