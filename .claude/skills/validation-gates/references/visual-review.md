# Visual review

Apply for changed UI/layout/resources or a requested visual audit. Inspect the
actual component in whole-screen consumers, significant states, light/dark theme
where supported, enlarged fonts, keyboard/insets and platform differences.

For a supplied design, use its authoritative source and record which state/node
was compared. Read available Figma assets/specs/screenshots through supported tools;
no private cache, mapping registry or export pipeline is assumed. Preserve declared
content and variant axes; do not invent missing design values to claim fidelity.

Use existing AppPreview/PreviewContainer states and authorized app screenshots.
Record actual observations, fix material mismatches and re-inspect changed states.
Do not add screenshot automation, test sources, capture dependencies or production
verification hooks without an explicit request. A source/token check or successful
build does not establish visual fidelity. State which rendering/runtime inputs
were unavailable, and whether they leave a material unresolved design decision.
