# Room persistence

Source of truth: `data-services/database/` (`Database.kt`, `entity/`, `dao/`, `models/`,
`migrations/`, `DatabaseBuilder.*.kt`, `DatabaseModule.kt`, `schemas/`). Inspect it before
relying on a detail below.

## Current shape (verified)

- `@Database(entities = [23 entities], version = 5, exportSchema = true)`,
  `@TypeConverters(StringListConverter::class)` (`List<String>` as one pipe-delimited string),
  `@ConstructedBy(DatabaseConstructor::class)` with `internal expect object DatabaseConstructor`
  in `DatabaseBuilder.kt` (the Room compiler generates the actuals).
- Migrations `Migration2To3`, `Migration3To4`, `Migration4To5`, each
  `internal object ... : Migration(a, b) { override fun migrate(connection: SQLiteConnection) }`,
  collected in `internal object DatabaseMigrations { val all: Array<Migration> }`. There is no
  1->2 migration: a version-1 install hits the destructive fallback.
- Exported schemas are committed under
  `data-services/database/schemas/com.grippo.services.database.Database/{1..5}.json`
  (`room.schemaLocation = $projectDir/schemas` in `RoomConventionPlugin`); the Room compiler
  rewrites the JSON for the current version during an authorized build.
- Android builder (`DatabaseBuilder.android.kt`): `Room.databaseBuilder<Database>(context, dbFile.absolutePath)`
  on `getDatabasePath("grippo_database.db")`, `.addMigrations(*DatabaseMigrations.all)`,
  `.fallbackToDestructiveMigration(dropAllTables = true)`, `.setQueryCoroutineContext(Dispatchers.IO)`,
  `.build().also { it.openHelper.writableDatabase }` (warm-up).
- iOS builder (`DatabaseBuilder.ios.kt`): `documentDirectory() + "/grippo_database.db"`, the same
  migrations and fallback, `.setDriver(BundledSQLiteDriver())`, `.setQueryCoroutineContext(Dispatchers.IO)`,
  no warm-up.
- Relation models in `models/` are `@Embedded` + `@Relation` classes: `TrainingPack`/`ExercisePack`,
  `DraftTrainingPack`/`DraftExercisePack`, `UserPack`, `ExerciseExamplePack` with
  `ExerciseExampleBundleWithMuscle` and `ExerciseEquipmentWithEquipment`,
  `EquipmentGroupWithEquipments`, `MuscleGroupWithMuscles`.
- `DatabaseModule` (`@Module(includes = [ContextModule::class]) @ComponentScan`) provides the
  `Database` and each of the ten DAOs through `@Single` provider methods.
- Range reconciliation in `TrainingRepositoryImpl` uses `TrainingDao.deleteByCreatedAtRangeExceptIds(from, to, ids)`
  when server IDs exist and `deleteByCreatedAtRange(from, to)` when the confirmed set is empty,
  then returns `Result.failure(AppError.Network.IncompleteResponse())` when the saved count differs
  from the received count; the policy is owned by [operation outcomes](operation-outcomes.md).
- Timestamps are persisted through `DateTimeUtils.toUtcIso(...)`.

## Rules

- Entity/DAO/Pack types stay below the Feature API. Entities retain storage wire strings; domain
  enum/date/duration promotion belongs to directional mappers.
- Store timestamps through `DateTimeUtils.toUtcIso(...)`; do not persist unnormalized local time.
- Keep parent/child foreign keys, cascade behavior and indices consistent. Use the existing relation
  packs and transactional boundaries for coherent multi-row reads/writes.
- Entity schema and migration changes need the authorized scope to cover them. Never assume
  prelaunch status permits dropping user data. The destructive fallback is intentional and must not
  be changed incidentally.
- Review schema version, registered migration chain and both platform builders. Schema JSON
  generated by an authorized build must match the intended schema; do not claim regeneration or
  runtime migration verification without having run it.

For a schema delta read [migration decisions](cookbook-room-migration.md).
