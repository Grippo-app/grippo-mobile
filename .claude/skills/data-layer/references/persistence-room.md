# Room persistence

Inspect `data-services/database/` for Database, entities, DAOs, relation packs, platform builders,
schemas and migrations. The actual source is authoritative for current version and registrations.

- Entity/DAO/Pack types stay below the Feature API. Entities retain storage wire strings;
  domain enum/date/duration promotion belongs to directional mappers.
- Store timestamps through `DateTimeUtils.toUtcIso(...)`; do not persist unnormalized local time.
- Keep parent/child foreign keys, cascade behavior and indices consistent. Use existing Room
  relation packs and transactional boundaries for coherent multi-row reads/writes.
- Entity schema and migration changes require authorization already covering that scope.
  Never assume prelaunch status permits dropping user data. The existing destructive fallback
  is intentional and must not be changed incidentally.
- Review schema version, registered migration chain and both platform builders. Schema JSON
  generated by an authorized build must match the intended schema; do not claim regeneration
  or runtime migration verification without having run it.

For a schema delta read [migration decisions](cookbook-room-migration.md).
